# PLUGG — Administrator Control Panel: System Audit & UI Blueprint for Lovable

> **Target Platform:** Plugg Music Streaming Platform  
> **Purpose:** Blueprint specification for Lovable to generate the standalone Plugg Admin Panel UI and its database / backend configuration surface.  
> **Timezone Core:** Africa/Kampala (`UTC+03:00`)  
> **Database:** PostgreSQL (with Neon/Cloudflare/local compatibility)

---

## 1. Executive Architecture Overview

Plugg operates a two-tiered system:
1. **Public Web Streaming App (`plugg.site`)**: For listeners and artists (music playback, discovery, playlists, artist profile, upload pipeline, and artist analytics).
2. **Administrator Control Panel (`admin.plugg.site` / Lovable App)**: A dedicated internal back-office site for administrators and content curators to audit incoming music, manage the 24-hour review SLA, verify artists, inspect audio transcoding pipelines, configure platform taxonomy, monitor fraud, and govern legal/PDPO compliance.

---

## 2. Comprehensive System Audit: What Needs Admin Configuration

### A. Release & Track Moderation Queue (`releases` & `tracks`)
Every music release uploaded by an artist enters the system as `under_review`. Admins must inspect the submission before it goes live.

| Database Field | Type | Description / Admin UI Control |
| :--- | :--- | :--- |
| `releases.status` | `enum` | `'under_review'` $\rightarrow$ `'scheduled'`, `'changes_required'`, `'published'`, `'processing'`. Can also be manually forced to `'draft'` or soft-deleted. |
| `releases.review_submitted_at` | `TIMESTAMPTZ` | Timestamp when the release was submitted by the artist. Admin UI computes live SLA countdown ($< 24\text{h}$ SLA badge: Green $<18\text{h}$, Amber $18\text{--}24\text{h}$, Red Pulsing $>24\text{h}$ breached). |
| `releases.reviewed_at` | `TIMESTAMPTZ` | Timestamp of admin decision. |
| `releases.reviewer_id` | `TEXT` | ID of the administrator who reviewed the submission. |
| `releases.review_feedback` | `TEXT` | Mandatory explanation sent to the artist when requesting changes (e.g. poor mix, clipping audio, misspelled feature credits, unauthorized cover art). |
| `releases.review_history` | `JSONB` | Array of audit events: `[{ date, action: 'submitted' \| 'approved' \| 'changes_requested' \| 'resubmitted', actorId, actorName, feedback, notes }]`. |
| `releases.release_date` | `DATE` | Target release date (`YYYY-MM-DD`). |
| `releases.go_live_at` | `TIMESTAMPTZ` | Calculated target go-live timestamp at **Midnight Kampala Time (`UTC+03:00`)**. If original date has elapsed during review, Admin UI forces selecting a new valid future date before approval. |
| `releases.label` | `TEXT` | Record label or "Independent". Admin can edit or standardize label names. |
| `tracks.plugg_track_id` | `TEXT` | Permanent standardized track ID (e.g. `PLG-2026-000042`). Auto-generated on upload. |
| `tracks.published` | `BOOLEAN` | Emergency takedown / visibility toggle. Setting `published = false` unpublishes a track immediately from streaming/discovery without deleting metadata. |
| `tracks.technical_validation` | `JSONB` | Extracted master audio properties: `{ format: 'wav'\|'flac', sampleRate: 44100\|48000\|96000, bitDepth: 16\|24, channels: 1\|2, isLossless: true, isStereo: true, is24Bit: true, valid: boolean }`. |
| `tracks.audio_processing_status` | `TEXT` | Transcoder status: `'pending'`, `'processing'`, `'completed'`, `'failed'`. Admin has a one-click **"Retry Transcoding"** button. |
| `tracks.audio_variants` | `JSONB` | Map of transcoded variants generated by FFmpeg: Streaming (`stream_64k`, `stream_96k`, `stream_160k`, `stream_256k`) and Downloads (`download_96k`, `download_160k`, `download_256k`). |

### B. Artist Verification & Discovery Curation (`artists`)
Admin governs the legitimacy of artist accounts and curates front-page highlights.

| Database Field | Type | Description / Admin UI Control |
| :--- | :--- | :--- |
| `artists.verified` | `BOOLEAN` | Blue/Brand verified badge toggle. Indicates verified identity / signed legal contract. |
| `artists.featured` | `BOOLEAN` | Controls whether the artist appears in the "Featured Artists" sidebar and Discover spotlights. |
| `artists.display_name` | `TEXT` | Artist stage name. Admin can correct typos or prevent impersonation. |
| `artists.username` | `TEXT` | Handle (`@artist`). Unique identifier used in public URLs (`plugg.site/artist/username`). |
| `artists.country` & `artists.city` | `TEXT` | Regional taxonomy (e.g. Uganda $\rightarrow$ Kampala, Jinja, Pakwach, Gulu, Arua, Mbarara; Kenya $\rightarrow$ Nairobi, etc.). |
| `artists.primary_genre` & `additional_genres` | `TEXT` / `TEXT[]` | Genre tags used in discovery filters. |
| `artists.phone_number` | `TEXT` | Mobile contact (critical for East African mobile money / artist KYC). |
| `artists.terms_accepted_at` | `TIMESTAMPTZ` | Legal compliance timestamp for Uganda Copyright and Neighbouring Rights Act audit. |
| `artists.fans`, `monthly_listeners`, `total_plays` | `INTEGER` / `BIGINT` | Counters. Admin can view anomalies and reset or recalculate from verified plays. |

### C. Users & Role-Based Access Control (`users`)

| Database Field | Type | Description / Admin UI Control |
| :--- | :--- | :--- |
| `users.is_admin` | `BOOLEAN` | Controls admin privileges. Admin panel can grant/revoke staff access. |
| `users.account_type` | `enum` | `'listener'` vs `'artist'`. Can manually upgrade a user to artist or link to an `artist_id`. |
| `users.email` | `TEXT` | User email address. Admin can view verification status, trigger password resets, or update emails. |
| `users.name` | `TEXT` | Full name or profile name. |
| Account Moderation | `Action` | Temporary suspension, permanent ban, or full deletion to comply with the Uganda Data Protection and Privacy Act (PDPO). |

### D. Taxonomy & Genre Management (`genres`)

| Database Field | Type | Description / Admin UI Control |
| :--- | :--- | :--- |
| `genres.id` | `TEXT` | Slug-based or UUID identifier. |
| `genres.name` | `TEXT` | Display name (e.g., *Afrobeats, Amapiano, Lugaflow, Bax Ragga, Kadongo Kamu, Gospel, Hip-Hop, Dancehall, DJ Mixes*). |
| `genres.slug` | `TEXT` | URL slug (e.g. `/genre/afrobeats`). |

---

### E. Telemetry, Play Fraud & Download Auditing (`plays` & `analytics`)

| Database Field / Concept | Type | Description / Admin UI Control |
| :--- | :--- | :--- |
| `plays.duration_played_seconds` | `INTEGER` | Played duration. Plays are only verified if duration $\ge 30\text{s}$. Anti-gaming dashboard flags repeat IPs and sub-30s bot spikes. |
| `plays.ip_address` & `session_id` | `TEXT` | IP / Session clustering to identify stream farming. |
| `tracks.download_count` | `BIGINT` | Total offline downloads. Breakdown by tier: Data Saver 96k vs Standard 160k vs High 256k. |
| Bandwidth / Storage | `Metrics` | Total storage consumed by `.storage/uploads` and variants; CDN egress bandwidth. |

---

### F. Midnight Publication Scheduler (Africa/Kampala UTC+03:00)
- Releases approved for a future date sit in `scheduled` status.
- Admin UI must show the **Upcoming Releases Calendar & Queue**:
  - Showing countdown to the next midnight (00:00 Kampala time).
  - List of tracks queued to flip from `scheduled` $\rightarrow$ `published`.
  - Manual override trigger ("Publish Now" for urgent releases).

## 3. Recommended Lovable UI Layout & Screen Structure

### Screen 1: Dashboard Overview (Executive Telemetry)
- **KPI Summary Cards:**
  - Pending Review Queue Count (with alert if $> 24\text{h}$ SLA breached)
  - Active Scheduled Releases for Upcoming Midnight (Kampala time)
  - Total Verified Artists vs Pending Verification Requests
  - Daily Qualified Streams ($\ge 30\text{s}$) & Total Downloads
- **Audio Pipeline Health:** Active transcoding jobs, completed variants count, failed transcoding alerts.

---

### Screen 2: Track & Release Review Queue (Primary Moderation Workspace)
- **Queue Table & Filter:**
  - Filter tabs: `All Pending`, `Approaching 24h SLA (<6h left)`, `Breached (>24h)`, `Changes Requested`.
  - Sort by: `Oldest Submission First` (First In, First Out).
- **Inspection Card / Drawer per Submission:**
  - **Cover Artwork Preview** & Release Metadata (Title, Artist, Release Date, Label, Genre).
  - **SLA Badge:** Live countdown with clear visual status.
  - **Integrated Audio Player:** Listen to the lossless master directly in the admin panel.
  - **Master Audio Inspector:**
    - Format (WAV/FLAC)
    - Sample Rate (44.1kHz / 48kHz / 96kHz)
    - Bit Depth (16-bit / 24-bit Studio Master)
    - Channel Configuration (Stereo / Mono warning)
  - **Audio Pipeline Status:**
    - Shows progress of 4 streaming variants (Opus 64k/96k/160k, AAC 256k) and 3 download variants (AAC 96k/160k/256k).
    - "Retry Transcoding" button if failed.
  - **Review History Timeline:** Previous submissions, feedback messages, and artist notes.
  - **Action Controls:**
    - **Approve Release Button:** Prompts for future midnight date if original date passed; marks `scheduled`.
    - **Request Changes Modal:** Requires written feedback with checklist options (Audio Clipping/Distortion, Metadata Mismatch, Miscredited Features, Low Quality Cover Art).

---

### Screen 3: Catalog Management (All Releases & Tracks)
- Comprehensive searchable catalog of every track on Plugg:
  - Columns: Plugg Track ID (`PLG-YYYY-XXXXXX`), Title, Artist, Status, Release Date, Plays, Downloads, Audio Processing Status.
  - Quick Actions: **Unpublish / Takedown (DMCA)**, Edit Metadata, Re-transcode Audio, View Technical Specs.

---

### Screen 4: Artist Directory & KYC Verification
- Table of all registered artists with filters: `Verified`, `Unverified`, `Featured on Home`.
- Actions:
  - Toggle **Verified Artist Badge** ($\checkmark$).
  - Toggle **Featured Artist** (promotes to Discover and Home carousels).
  - Edit location (Country & City dropdowns).
  - Review Terms Acceptance timestamp.
  - Impersonation and profile moderation (avatar, bio, links).

---

### Screen 5: System Taxonomy (Genres & Curated Shelves)
- Genre CRUD: Add new East African or global genres, edit slugs, update cover art cards.
- Order / Prioritize trending genres.

---

### Screen 6: User Governance & Access Control
- User list with role indicators (`Admin`, `Artist`, `Listener`).
- One-click Admin grant/revoke.
- PDPO compliance toolkit: User account erasure request processor, data export, and audit log.

---

### Screen 7: Streaming Telemetry & Anti-Gaming Inspector
- Live plays stream inspector with IP grouping and duration metrics.
- Flag anomalous play spikes (e.g. 10,000 plays from a single IP within 1 hour).
- Stream purging tool: deduct fraudulent plays from `total_plays` and `plays` table.

## 4. API Endpoints / Server Functions Contract for Admin Integration

The admin panel can connect to Plugg via the existing TanStack Start server functions or REST endpoints:

1. `GET /api/admin/releases/review-queue`: Fetches pending submissions with technical specs and SLA status.
2. `POST /api/admin/releases/approve`: `{ releaseId: string, newReleaseDate?: string }`
3. `POST /api/admin/releases/request-changes`: `{ releaseId: string, feedback: string }`
4. `POST /api/admin/tracks/retry-processing`: `{ trackId: string }`
5. `POST /api/admin/tracks/takedown`: `{ trackId: string, reason: string }`
6. `POST /api/admin/artists/verify`: `{ artistId: string, verified: boolean }`
7. `POST /api/admin/artists/feature`: `{ artistId: string, featured: boolean }`
8. `POST /api/admin/genres/manage`: `{ action: 'create' | 'update' | 'delete', genre: Genre }`
9. `POST /api/admin/users/role`: `{ userId: string, isAdmin: boolean }`
10. `GET /api/admin/system/scheduler`: Checks Kampala midnight release queue and cron status.
